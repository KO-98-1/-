# SW 표준 산출물 자동 작성 앱

모델을 고르고 회의록·메모·요구사항 같은 텍스트를 넣으면, 「CBD SW개발 표준 산출물 관리 가이드」(2011.12) 양식의
산출물(Word)을 분석 → 설계 → 구현 → 시험 순으로 자동 작성합니다. 양식·검증·문서 생성은 킷의 `swd` 엔진이 맡고,
앱은 모델 호출과 진행 관리를 맡습니다.

## 실행

```bash
cd app
npm install          # 처음 한 번 (모델 SDK)
npm start            # http://127.0.0.1:4817 을 브라우저로 엽니다
```

Windows는 `start.bat`, macOS·Linux는 `./start.sh`를 더블클릭하거나 실행해도 됩니다.
브라우저 대신 별도 창(데스크톱 앱)으로 쓰려면 `npm run desktop` (처음 한 번 Electron 약 100MB를 내려받습니다).
킷의 엔진 의존성(Mermaid 등)이 없으면 먼저 `node ../.claude/skills/sw-deliverables/scripts/swd.mjs setup`을 한 번 실행하세요.
다이어그램을 그리려면 Chrome 또는 Edge가 있어야 합니다.

## 모델 선택 (⚙ 모델 설정)

| 제공자 | 필요한 것 | 작성 방식 |
|---|---|---|
| Codex CLI | `codex` 설치·로그인(ChatGPT 계정 또는 OpenAI 키) | 에이전트: 모델이 YAML 파일을 직접 쓰고 검증 명령으로 고칩니다 |
| Claude Code CLI | `claude` 설치·로그인 | 에이전트 |
| OpenAI API | API 키(또는 `OPENAI_API_KEY`), 모델 이름. OpenAI 호환 서버는 Base URL | 텍스트: 산출물 하나씩 생성 → 앱이 저장·검증 → 오류를 돌려주며 수정 |
| Anthropic API | API 키(또는 `ANTHROPIC_API_KEY`). 모델을 비우면 `claude-opus-5` | 텍스트 |

- API 키는 `~/.config/sw-deliverables/settings.json`(Windows: `%APPDATA%\sw-deliverables`)에 소유자만 읽을 수 있게 저장되고, 화면에는 끝 4자리만 보입니다.
- Anthropic API는 거절 대체(server-side fallback)를 켜서 호출합니다(`claude-opus-5`, `claude-fable-5-1`).
- 작성 방식은 기본값 `자동`(CLI는 에이전트, API는 텍스트). CLI도 텍스트 방식으로 돌릴 수 있습니다.

## 흐름

1. **프로젝트 만들기** → `~/SW산출물/<이름>/` 에 산출물 작업 폴더가 생깁니다.
2. **자료 넣기**: 회의록 / 아이디어 / 수정사항 / 참고문서 (txt, md, docx, hwp, hwpx, pdf) 또는 텍스트 붙여넣기.
3. **실행**: 단계(분석·설계·구현·시험)를 고르고 시작.
   - 시스템명·서브시스템이 비어 있으면 마스터가 자료를 읽고 설정을 제안해 채웁니다.
   - 단계마다: 준비(배분표·공용 DB·데이터 소유권 표) → 선행 산출물 기준 생략 → 서브시스템별 병렬 작성 → 병합 검증·수정 → 제·개정 이력 → 문서 생성 → 검토 리포트.
   - "단계마다 멈추고 검토"를 켜면 단계가 끝날 때마다 멈추고 [계속]을 기다립니다.
4. **결과**: 서브시스템별 Word 산출물, DDL, 검토 리포트(AI 제안·미정·질문지·검증 결과), 전체 ZIP.
5. **수정사항 반영**(실행 탭): 자료 탭에 '수정사항'으로 넣은 요청마다 [영향 분석] → 변경 목록·영향 산출물·회의 결정과의 충돌 확인 →
   체크한 변경만 [반영] → 검증 → 제·개정 이력 → 문서 재생성.
6. **검증·수정만**: 산출물을 직접 고쳤거나 오류가 남았을 때, 새로 쓰지 않고 검증 오류만 고친 뒤 문서를 다시 만듭니다.

자동 점검: 단계마다 검증(ID·참조·출처·가이드 규칙·추적성), 설계 중 서브시스템 간 연결 보완(테이블 FK로 엔티티 관계, 마스터가 컴포넌트 의존 —
아키텍처 작성 전), 작성되지 않은 산출물 재요청, 테이블 설계를 내장 PostgreSQL에서
실제로 실행해 보는 DDL 점검(`@electric-sql/pglite`가 설치돼 있으면).

## 정확성 원칙

- 입력 근거가 있는 값만 사실로 쓰고, 가이드상 도출되는 설계는 **노란 음영(AI 제안, 검토 전)** 으로 표시합니다.
- 가이드 작성 목적의 핵심 내용을 쓸 **근거가 부족한 산출물은 만들지 않습니다.** 결과 화면의 "만들지 않은 산출물"에 사유와 필요한 자료가 나옵니다. 자료를 더 넣고 다시 실행하면 작성됩니다.
- 결과서(단위·통합·시스템·인수시험 결과서)는 실제 시험 결과가 있을 때만 문서가 됩니다.

## 명령줄

```bash
node cli.mjs providers                                  # 사용 가능한 제공자
node cli.mjs test --provider anthropic                  # 연결 확인
node cli.mjs run --project ~/SW산출물/데모 --input ./회의록폴더 --provider codex-cli --model gpt-6-luna
node cli.mjs run --project ~/SW산출물/데모 --stages design,implementation --repair   # 검증·수정만
```

`--input` 폴더의 하위 폴더 이름이 회의록/아이디어/수정사항/참고문서면 그 종류로, 아니면 회의록으로 넣습니다.

## 보안

입력 자료는 선택한 AI 서비스로 전송됩니다. 반출이 제한된 자료는 넣지 마세요. 서버는 이 컴퓨터(127.0.0.1)에서만 열립니다.
