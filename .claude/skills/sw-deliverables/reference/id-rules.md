# ID 규칙과 근거

## 산출물(문서) ID — 가이드 Ⅱ.3 그대로

`프로젝트ID + 서브시스템ID + 산출물코드 + 순서번호` → `PRJ_SA_REQ_010` (가이드 사례: `SS_SA_REQ_010`)
시스템 공통 산출물은 서브시스템 자리에 `ALL`을 쓴다. 파일 이름 앞부분이 산출물 ID다.

|---|---|---|---|---|---|
| R1 | 사용자 요구사항 정의서 | REQ | D9 | 데이터베이스 설계서 | DBD |
| R2 | 유스케이스 명세서 | UC | D10 | 통합시험 시나리오 | ITS |

## 항목(요소) ID — 공공 SW사업 통용 규칙

형식 `유형코드-서브시스템-일련번호` (예: `UC-SA-001`). 웹에서 통용되는 방식(유형 접두어 + 업무영역 + 번호, 한 번 부여하면 재사용 금지)을 따르고, 가이드의 "서브시스템 ID 포함" 원칙을 유지했다.

| 유형 | 형식 | 예 |
|---|---|---|
| 요구사항 | `{분류코드}-{sub}-{nnn}` | `SFR-SA-001`, `PER-COM-001` |
| 액터 / UCD / 유스케이스 | `ACT-{sub}-{nn}` / `UCD-{sub}-{nn}` / `UC-{sub}-{nnn}` | `UC-SA-003` |
| 시퀀스도 / 클래스도 / 클래스 | `SD-` / `CD-` / `CL-{sub}-{nnn}` | `SD-SA-003` (UC 번호와 맞춤) |
| 화면 / 출력물 | `SCR-{sub}-{nnn}` / `RPT-{sub}-{nnn}` | `SCR-SA-010` |
| 컴포넌트 / 컴포넌트 인터페이스 | `CMP-{sub}-{nn}` / `CIF-{sub}-{nnn}` | |
| 연계 인터페이스 | `IF-{sub}-{nnn}` | |
| ERD / 엔티티 | `ERD-{sub}-{nn}` / `ENT-{sub}-{nnn}` | |
| 데이터베이스 / 테이블 / 인덱스 | `DB-{nn}` / `TB_{sub}_{영문명}` / `PK_…`,`IX_…_01` | `TB_SA_ORDER` |
| 시험 | `ST-` `IT-` `UT-` `AT-{sub}-{nnn}`, 케이스 `{상위ID}-{nn}` | `IT-SA-001-02` |
| 프로그램 / DDL | `PGM-{sub}-{nnn}` / `DDL-{sub}-{nnn}` | |

### 요구사항 분류코드 (공공 SW사업 제안요청서 요구사항 분류)

SFR 기능 · PER 성능 · SIR 인터페이스 · DAR 데이터 · TER 테스트 · SER 보안 · QUR 품질 · COR 제약사항 ·
ECR 시스템 장비 구성 · PMR 프로젝트 관리 · PSR 프로젝트 지원. 가이드 R1의 '운영 요구사항'은 대응 코드가 없어 `OPR`을 추가했다.

### 근거

- 가이드 Ⅱ.3 산출물 ID 부여 기본방법(프로젝트에 별도 규칙이 있으면 그것을 따름)
- IT위키 'RFP' — 요구사항 분류와 고유번호 접두어(SFR·PER·ECR·SIR·DAR·TER·SER·QUR·COR·PMR·PSR)
- 요구사항 ID 체계 실무 글(TreeSoop 2026) — `구분-업무영역-일련번호`, 한 번 부여한 번호 재사용 금지, 화면·테스트 ID도 같은 업무영역 코드로 통일
- 공공기관 데이터베이스 표준화 관행 — 테이블 물리명 `TB_` 접두어

프로젝트 규칙이 따로 있으면 `sw-config.yaml`의 `ids` 절만 바꾸면 검증기·다음 번호 계산이 그 규칙을 따른다.
